# 资料与译本处理

## 来源清单

为每类资料记录官方 URL、课程学期/教材版次、实际获取日期、内容类别、许可依据、离线状态。翻译另记作者/贡献者、上游链接和提交号。课程网站会切换学期，历史站可能需要登录；标题、日历和作业页面一起核对。

“较近且完整”的判断要能解释：课程是否已结束、目录是否覆盖期末、主要作业是否已发布、公开入口是否可访问。没有查遍全部学期时，不声称“全网最新完整版本”。不要把刚更新、尚未完成的新教材版次拼入旧版而不标注。

教材可全文收录与作业仅能提供导航，是可以并存的交付范围。明确记录，不把版权限制悄悄替换成产品功能缺失，也不在无法完整收录时把题目索引称作完整原题。

## 优先复用中译本

搜索原书英文名、中文名、版次和 translation/中文关键词。优先查看译本自己的仓库、README、许可和目录，而非转载聚合站。

核对：

- 中文目录与所用英文版的章节和小节编号是否对应，是否有未译或仅标题的章节。
- 译者是谁，是否存在来源与许可，正文许可和站点代码许可是否分别说明。
- 代码块、公式和配图是否完整，是否依赖某个站点组件才能显示。
- 是否保留旧学期的作业映射；不要把旧映射直接当作本次所选学期。

能匹配就用现成全文并注明“社区译本”；只做了版式整理时不能声称重新翻译或逐句审校。没有合适版本时才自行翻译，保持限定、数字、因果与术语，按完整目录持续推进；不能用机器摘要填充未翻完的章节。

结构核对可以使用节号集合；翻译质量需要实读与对照。发现漏节、代码不一致或明显含义错误时修复或准确记录，不能仅因上游自称完整就跳过检查。

## Markdown 转换中易损的内容

- HTML 中的 `div.example` 等可能装有保留空白的完整程序。先识别，再转换成代码围栏；直接转普通段落会丢缩进。
- 使用真实 Markdown 解析器处理代码围栏和链接。正则扫描全文可能把代码里的 `obj['method'](x)` 错当成本地链接，也容易混淆代码内容中的反引号。
- 保留代码块正文。统一 `py`/`python`、`sh`/`bash` 等语言标记时，只改围栏信息；交互提示符和输出不是错误代码，不为通过脚本编译而删除它们。
- `Python Tutor`、运行按钮和视频不等于正文。离线稿保留静态代码，将演示转为带说明的在线入口；不要自动运行远程嵌入组件。
- VitePress 的 `::: details`、Vue 组件、站点绝对图片路径须适配为 Obsidian 能读的结构。移除组件前确认没有连正文一并删除。
- 图片只在许可允许、获取符合任务范围时保存本地；失败图片要记录，不能保留一个看似离线但实际断裂的链接。
- 英文锚点与中文标题通常不同。跨节引用应重写到正确页和锚点；不能机械复制英文 `#anchor` 并假定中文能定位。
- 合订本的同名标题与来源节号会重复。采用稳定且唯一的节级锚点，重写本地导航，避免指回作者机器的绝对路径。
